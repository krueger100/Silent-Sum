# SilentSum Billing (Pro + Cloud) Implementation Plan

> Status 2026-09-21: executed inline in one session (all 14 tasks); every check green. Deploy and PayMongo configuration remain manual, see docs/billing.md.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Sell SilentSum Pro (₱299 once, permanent) and SilentSum Cloud (₱99/month) through PayMongo, with Firebase as the authoritative entitlement store, without touching any vault, PIN, encryption or recovery flow.

**Architecture:** The app calls Cloud Functions (`functions/`, codebase `silentsum`) that create PayMongo Checkout Sessions; PayMongo confirms through a signed webhook; the functions write `users/{uid}/billing/entitlements`, which the app mirrors into a zustand store and a secure-store cache. Rules deny every client write to billing data and gate cloud writes on `cloud.accessUntil`.

**Tech Stack:** Expo SDK 57 / RN 0.86 / React 19 / TypeScript 6 strict / Jest + RNTL 14 (app); Node 22 / firebase-functions 7 / firebase-admin 14 / Jest + ts-jest (backend); PayMongo REST v1.

**Spec:** `docs/superpowers/specs/2026-09-21-billing-design.md`

## Global Constraints

- `pro` never expires; `cloud` is active iff `accessUntil > now`. Never couple the two.
- No PayMongo key anywhere in the app or tracked source. Client never reads its own `isPro` from anything but the server mirror; server never reads client-sent entitlement state.
